ChipMachine — App Review Information

Description

ChipMachine is a fun visual music player and indexed collection browser for retro computer and console chip music.

Explore, search, and instantly play a large library of retro game and historical computer music formats from legendary systems such as Sinclair ZX Spectrum, Commodore 64, Amiga, Atari 800/ST, Amstrad CPC, Acorn Archimedes, Sam Coupe, older gaming consoles, retro Japanese computers, and other classic platforms. Selected retro podcasts and radio stations can also be streamed.

Key Features

* Browse and search a large multi-format database of retro music collections.
* Play hundreds of classic tracker and chip music formats.
* View artwork and metadata associated with collections and songs.
* Support multiple playback engines for different historical systems.
* Filter and discover music by platform, format, collection, and other categories.
* Amiga-intro-style music visualiser

Reviewer Testing Instructions

After launching ChipMachine:

1. Type to search for a song and/or composer.
2. Use UP/DOWN to navigate results and ENTER to play the selected song.
3. Press TAB multiple times to cycle through various content filters.
4. Press CTRL+H to display the help screen.

Playback requires network connectivity because the audio files are accessed on demand when the user initiates playback. Playback of local music files is also supported in which case there is no need for network.

Legal and Technical Notes

0. Introduction

ChipMachine is a standalone application. It does not execute external utilities and does not require access to user files outside the application container and outside the locations explicitly selected by the user (local files playback).

The app includes embedded playback libraries required to decode supported music formats. Audio decoding and playback are performed locally on the user's Mac after the requested audio data is retrieved.

The application includes a built-in indexed music database. No external files or accounts are required to verify the application. The database contains metadata aggregated from publicly available retro computing music archives.

1. Licensing and Open Source Components

No GPL-licensed code or libraries are used in ChipMachine.

All third-party components included are compatible with App Store distribution and are used under their respective licenses. The application includes only libraries and components whose licenses permit their use in a distributed macOS application.

See Credits.rtf for further details.

2. No YouTube Playback

ChipMachine does not play YouTube content, does not bundle or execute yt-dlp or any other download utility, and does not spawn external processes to resolve media URLs. No helper executable of any kind is present in the bundle: Contents/MacOS/ contains only the main binary.

This holds structurally, not by convention. No YouTube playback plugin is compiled into the application. No Lua binding capable of running a shell command is compiled into it either, and no directory named for a download utility is added to the process PATH. The packaging process additionally verifies that no bundled Lua script references a subprocess call, and fails outright if one does.

The music catalog itself contains no YouTube entries. Any indexed row whose location is a youtube.com or youtu.be URL is discarded when the database is built, so no such row is ever searchable or selectable.

For completeness, a few YouTube-related strings are visible in the binary. None is a playback path:

* "youtube.com/" and "youtu.be/" — the filter described above. These strings are what REMOVES YouTube entries from the catalog.

* "https://img.youtube.com/vi/" — a thumbnail URL template. YouTube thumbnails are used as artwork for some catalog entries.

* "YouTube" and "YouTube - " — display labels for the catalog's platform/format column.

* A User-Agent literal beginning "com.google.android.apps.youtube.vr.oculus/", inside the media-decoding component. It would only ever be sent when fetching an already-resolved googlevideo.com stream URL. ChipMachine never resolves, produces or requests such a URL, so the string is unreachable.

All are inert: a filter, artwork and metadata references, and one unused constant.

3. POSIX Subprocess API Imports (system, popen, fork, execve)

Static analysis will show that the executable imports the POSIX subprocess symbols system, popen, pclose, fork, execve and execvp.

ChipMachine does not execute shell commands, does not spawn user-provided processes, and does not invoke external commands during normal operation. There is no helper executable in the bundle for any of these to launch.

The imports are pulled in by third-party libraries linked for unrelated reasons, and are not reachable:

* JUCE (juce_core). ChipMachine plays Amstrad CPC formats (STarKos, Arkos Tracker) using the Arkos Tracker 3 engine, which is built on JUCE. JUCE's general-purpose process and file utilities reference system(), fork() and execve(). Only the audio and data-structure parts of that library are used; the process utilities are never called.

* The embedded Lua runtime, whose standard "io" and "os" modules define io.popen() and os.execute(). ChipMachine opens only the base, package and string libraries — the io and os modules are never registered in the interpreter, so neither function is reachable from any script.

Separately, the bundled SunVox library probes for optional external conversion utilities as part of its own media handling. ChipMachine does not use that code path, and SunVox is a dynamic library: its imports are not part of the main executable's import table.

4. Lua Runtime Search Paths and App Sandbox Compatibility

ChipMachine uses Lua through an embedded Lua runtime.

The application does not load user-provided Lua scripts and does not dynamically load Lua modules from external filesystem locations.

No runtime filesystem access outside the application bundle is required for Lua operation.

The application operates correctly under App Sandbox with embedded resources only.

5. Audio Content and Network Access

No audio files are embedded with the application.

Only publicly available metadata is indexed. Individual songs are retrieved from publicly available online archives when playback is requested by the user.
