mod	SoundTracker / SoundTracker 2.6 / NoiseTracker / Protracker / StarTrekker / ChipTracker
The original legendary tracker music editor, created by Karsten Obarski (and the most common extension). The MOD format was the first file format for tracked music on the Commodore Amiga. A very basic version of this format (with only very few pattern commands and short samples supported) was introduced by Karsten Obarski’s Ultimate SoundTracker. It was designed to use 4 channels each with one voice. Ultimate SoundTracker was soon superseded by NoiseTracker and ProTracker, which allowed for more tracker commands (effects), longer samples, more patterns and other improvements. Later, variants of the MOD format that appeared on the Personal Computer extended the number of channels, added panning commands (the Amiga’s four hardware channels had a pre-defined stereo setup) and expanded the Amiga’s frequency limit, allowing for more octaves of notes to be supported. Arguably one of the most widespread tracker formats (also due to its use in many computer games and demos), it is also one of the simplest to use, but also only provides few pattern commands to use. Instruments cannot be used in the MOD format, only 8-bit samples with a maximum size of 128 KB per sample and with a limited set of parameters. Initial tempo, number of rows (always 64), and the “time signature” cannot be defined (always uses the highlight values provided in the Display setup). There is limited sample control and few global settings. The 2.6 version by Mnemotron/Spreadpoint differs from Sound/Noise/ProTracker in that each pattern is no longer made up from 4 joined tracks, but instead channel uses its own sub-patterns. This enables you to create a drum beat and repeat that without having to copy and paste it into each track. File format is similar to that of Protracker. NoiseTracker is an evolution of the Soundtracker format by Per Tufvesson (Mahoney/Northstar) and Anders Berkeman (Kaktus/Silents). Protracker is the venerable successor of Noisetracker, originally created by the Amiga Freelancers (Lars and Anders Hamre, Sven Vahsen and Rune Johnsrud), followed by Peter Hanning and Anders Ramsay for version 2.1 to 2.3, then by the Cryptoburners (Ivar Just Olsen, Tom Bech and Bjarte Andreaeassen). StarTrekker is a Soundtracker clone created in 1990 by Björn Wesen (Exolon/Fairlight).  The "4AM" replayer can play synthetic sound samples. ChipTracker (also known as KRIS Tracker) is a module packer created by KRIS/Anarchy for use by Matthew Simmonds (4-Mat/Anarchy). If you read all this text give yourself a pat on the back!

sid	.sid file format container used to play music from the Commodore 64. Unlike modern audio files (MP3 or WAV) which store digitized waveforms, or MIDI files which store raw musical notes, a .sid file contains actual MOS 6502/6510 machine language code. When you play a SID file, a dedicated player must emulate the C64's microprocessor and its specialized MOS Technology Sound Interface Device (SID) chip to execute the code and generate the sound in real time. The primary data block consists of the C64 assembler code (the music player routine) and the associated music data (patterns, instruments, and tracking notes). When executed by a player, the code directly modifies the 29 hardware registers of the SID chip 50 times (PAL systems) or 60 times (NTSC systems) per second to manipulate the oscillators, envelopes, and filters. A single .sid file can package multiple tracks or sound effects (often sharing the same instrument data), known as "subtunes". From 1990 to 1994, Sundell and Birk developed a SID player for their Amiga demo "The 100 Most Remembered 64 Game-Tunes" and for their tool PlaySID. Originally, a SID tune was spread over two files. Due to popular demand, a one-file format was introduced in PlaySID V2.2. This was the first version of the SID format.

nsf	NES Sound Format: music ripped from Nintendo NES/Famicom games, devised by Kevin Horton in 1999 (originally "NESM"); the 6502 sound code plus a small header, replayed on an emulated 2A03. Hugely popular for original chiptune composition. It is the definitive standard for preserving and composing Nintendo Entertainment System chiptunes. It isolates the audio data from a game ROM, allowing the music to play without running the actual game. Contains the original MOS Technology 6502 machine code instructions and register writes that drive the audio.Target Hardware: Replayed by emulating the Ricoh 2A03 (NTSC) or 2A07 (PAL) microprocessors, which contain the NES Programmable Sound Generator (PSG). It stores metadata like song count, starting track, load/init/play addresses, game title, artist, and copyright strings. Kevin Horton, known prominently online by his handle Kevtris, is a legendary hardware hacker and electrical engineer who single-handedly invented the NES Sound Format (NSF) spec. He originally dubbed the file extension .NESM (NES Music) when he designed it, before the community universally shortened the extension to .NSF. Kevtris is currently (2026) Director of FPGA Development at Analogue. He designed the internal core logic from scratch for the Analogue Nt Mini, Super Nt, Mega Sg, and Analogue Pocket. He also engineered HiDef NES: the popular internal hardware mod that allows original NES consoles to output pixel-perfect, lag-free 1080p video and audio via HDMI.

nsfe	The NSFE (NES Sound Format Extended) is an upgraded variant of the standard NSF (Nintendo Sound Format) container. The original NSF format stores raw audio code and data ripped directly from Nintendo Entertainment System (NES) games, but its rigid header severely limits metadata. NSFE solves this by using a flexible, chunk-based structure (similar to PNG files) to store rich, per-track information. The original NSF format only allows one global game title and author name for the entire file. NSFE supports unique titles, composers, and artists for every individual track. Standard NSF files rely on the player to guess when a track ends, often resulting in sudden cuts or infinite loops. NSFE embeds exact track lengths, fade-out times, and post-fade silence durations. Playlists can be customized, allowing tracks to be reordered logically (e.g., matching the game's soundtrack CD) rather than following the chaotic internal memory order of the ROM. It allows developers to flag and skip empty, unused, or duplicate sound effect tracks inside the file.

ym	ST-Sound (.YM) is a register-dump audio file format designed to capture and play back chiptunes from systems using the AY-3-8910 or YM2149 sound chips. Created by Arnaud Carré (known as Leonard of the demogroup Oxygene) specifically for his emulator, ST-Sound. Rather than storing executable code, it records a raw dump of the sound chip's internal registers, typically sampled 50 times per second (50 Hz). Covers music from multiple vintage 8-bit and 16-bit computers, including the Atari ST, Amstrad CPC, and ZX Spectrum. Files are natively compressed using LHA (.lha/.lh1) compression to significantly reduce the size of the repetitive register data. Unlike SNDH, YM files do not require a Motorola 68000 CPU emulator to play, making them much easier to implement in lightweight, cross-platform modern players. YM1-YM3 were early, uncompressed and basic structural formats. YM5 is the most widely adopted version, introducing advanced header information, loop points, and precise clock speed settings for different computers (e.g., 2 MHz for Atari ST vs. 1.77 MHz for ZX Spectrum). While standard .ym files (created by Leonard/OXYGENE) contain interleaved register data for the YM2149 or AY-3-8910 chips, .ymst files usually indicate a modified version containing pre-rendered or specifically formatted stereo streams. Like the base .ym format, it does not store musical notation or machine code (like a .SID or .MOD file). Instead, it is a frame-by-frame dump of the exact register values required to synthesize the chiptune. Original AY/YM chips output 3 native mono channels. A stereo variant like .ymst splits these channels across left and right audio outputs (e.g., hard-panning channels A, B, and C) to create an enhanced spatial experience. Both the base .ym and .ymst variants are designed to be replayed directly by the StSound-style engine (created by Arnaud Carré). This highly optimized C++ library handles the CPU-free rendering of the chip's sound parameters. Because StSound acts as a universal emulator, these files allow modern systems to accurately recreate the iconic 8-bit chiptune sounds originally pioneered by platforms like the Atari ST and Amstrad CPC.
