# ChipMachine — working notes for Claude

macOS chiptune player. C++/CMake/Ninja, Apple Silicon, macOS 26 (Tahoe) only.
See `README.md` for the user-facing story and `docs/` for App Store material.

## Where things are

This git repo is `chipmachine/`, but it sits inside a **workspace directory**
`chipmachine-as/` that is *not* a git repo. Build trees, the packaged `.app`
bundles and the 9.7 GB `zxart` music corpus are siblings of the repo, not in it.

| Path | What |
| --- | --- |
| `chipmachine-as/` | workspace root (not tracked) — sessions run from here |
| `chipmachine-as/chipmachine/` | **this repo** |
| `chipmachine-as/build/` | plus variant build tree |
| `chipmachine-as/build-mas/` | mas variant build tree |
| `chipmachine-as/*.app`, `*.pkg`, `*.zip` | generated release artifacts |
| `chipmachine/src/` | the app |
| `chipmachine/external/` | ~20 **vendored** dependency forks (see below) |
| `chipmachine/data/` | shipping assets ONLY |
| `chipmachine/data-notbundled/` | build-time inputs, scrape data, project docs |
| `chipmachine/scripts/` | collection/database builders (`DB_UPDATE_PROCESS.txt`) |

## Build, run, test

One build dir per variant. Always Ninja + Release — Debug behaves materially
differently (Release-only heap bugs vanish; JUCE `jassert` noise appears).

```bash
cmake -S chipmachine -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
```

```bash
cmake -S chipmachine -B build-mas -G Ninja -DCMAKE_BUILD_TYPE=Release -DCM_VARIANT=mas
```

Build and run from the build dir: `ninja chipmachine cmtest`, then `./chipmachine -d`
or `./cmtest`. cmtest self-locates its fixtures, so it works from any cwd.

**Run the whole cmtest suite, not a single filter.** Heap-layout and
uninitialized-memory bugs only surface once earlier plugins have dirtied the
heap; run it a few times for nondeterministic ones.

There is exactly one build dir per variant and **no sanitizers** — the ASan
runtime deadlocks pre-`main` on this macOS. Don't reintroduce `-DSAN=` /
`-fsanitize` / `build-asan/`.

## Hands off

- **`package_app.sh`** — the release step, run by the user. Never invoke it.
- **`*.app` bundles** — generated by that script. Never edit or treat as source
  of truth; the `chipmachine/` copy of any data file is authoritative.
- **`data-notbundled/TOODOO.txt`** — the user's hand-maintained list. Read only.

## Vendored dependencies

`external/` holds flattened forks, provenance (URL + SHA) in
`external/VENDORED.md`. An engine used by exactly **one** plugin lives inside
that plugin's directory; only shared/infra deps (`zxtune`, `libkss`, `apone`,
`musicplayer`, `lua`, `sol2`, …) stay at `external/` root. Vendor new engines
inside the plugin from the start.

`.gitignore` matches ~2000 legitimate tracked files under `external/`
(`*.a`, `*.o`, `build/`, `generated/`, `*.db`). A new vendored dep must be added
with `git add -f`. Local patches to vendored libraries (UADE's
`eagleplayer.conf` reroutes especially) must be re-applied on every revendor.

## Adding a music format

1. New plugin under `external/musicplayer/src/plugins/<name>plugin/`, or a patch
   to an existing vendored library (libopenmpt `Load_*.cpp`, GME headers).
2. Register in **`src/plugin_register.cpp`** — both the `extern` declaration and
   the call. Miss it and the format is GUI-silent while cmtest still passes,
   because `testPlugin<>` constructs plugins directly.
3. Add the extension to `CMakeLists.txt`'s `MUSICPLAYER_PLUGINS` **and**
   `external/musicplayer/src/plugins/plugins.h`.
4. Add a `TEST_CASE("Name","[music]") { testPlugin<musix::XPlugin>(...); }` with
   fixtures under `testmus/<plugin>/`.

**Extension collisions are the norm.** Many extensions map to two or more
formats. Resolve by content-gating on magic bytes in `canHandle`/`load`, never
by extension alone. A format with no open replayer should *decline* so it Skips
rather than fails.

## Traps that have bitten repeatedly

- **`NDEBUG` is never defined, even in Release.** `assert()` in vendored C is
  live in the shipped app — a desynced libxmp loader `abort()`s the whole
  process. Probe new loaders with asserts ON, and never silence one with
  `-DNDEBUG`: those asserts guard array indices.
- **Every plugin must output 44100 Hz interleaved stereo.** The app feeds
  `getSamples` into a fixed 44100 device and *ignores* `getHZ()`. Resample and
  duplicate mono yourself.
- **`getSamples` must return -1, not 0**, on end or stall, or the GUI freezes.
- **`createPlugins()` uses `stable_sort`** — most plugins are priority 0, so
  registration order in `register_plugins()` decides who claims a shared
  extension. Inserting a plugin can silently re-route thousands of unrelated
  songs; diff `cmtest priority_map` before and after. If two plugins share an
  extension and neither content-gates, say so with `priority()`.
- A fixture dropped into `testmus/` is **not** a routing regression guard —
  `testPlugin` turns a `canHandle` miss into a yellow Skip, never a failure.
  Routing needs explicit `REQUIRE(a.canHandle(f))` + `REQUIRE_FALSE(b.canHandle(f))`.
- Some engines need `-fsigned-char`; some need `ld -r` to localize colliding
  globals; widths must be explicit on LP64.

## The two variants

`variants.conf` is the single source of truth for product identity. `plus`
(GitHub, Developer ID, has YouTube) and `mas` (App Store, sandboxed, no yt-dlp).

**The model is subtractive: `mas` = `plus` minus only what App Store rules
forbid.** Default for any code is *shared*. Order of preference when behaviour
must differ: (1) one code path that self-gates at runtime — e.g. the sandbox file
access checks `isSandboxed()` and no-ops in plus; (2) config/plist/entitlements
divergence; (3) `#ifdef CM_MAS` **only** when the code must be physically absent
from the binary, as with the yt-dlp spawn path.

## Data and licensing

`data/` is copied whole into the signed bundle, so it holds only what the running
app opens. Any build-time input, scrape file or document goes in
`data-notbundled/`. (Three exceptions stay in `data/misc/` with no runtime
reader — `formats.png`, `search.png`, `amegas.png` — external sites hot-link
them.)

Licence text lives in exactly two files: **`LEGAL`** (everything in both builds)
and **`LEGAL-PLUS`** (the `CM_HAVE_*`-gated engines and payloads plus builds
only). `data/misc/Credits.rtf` is a preamble stub; `package_app.sh` concatenates
the real credits at package time. Never hand-edit a licence list, and keep
engineering narrative out of `LEGAL*` — counts, measurements, symbol tricks,
routing behaviour and build flags belong in the plugin's own README.
